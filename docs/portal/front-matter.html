Como este site é publicado

O site não é a raiz do repositório: ele é montado arquivo por arquivo pelo workflow .github/workflows/pages.yml, que roda a cada push em main que toque um dos caminhos publicados. O que não estiver escrito lá não vai ao ar.

Por que os relatórios ficam um nível abaixo da raiz

Os dois HTML de relatório referenciam as capturas por ../evidencias/. Publicá-los em /relatorios/ faz esse caminho resolver em /evidencias/ sem precisar reescrever os arquivos.

Escopo da publicação

DentroFora
Painel HTML puro (html/) Painel React (frontend/) — depende da API em runtime
Especificação SDP #5211 Backend FastAPI (backend/) — Pages não executa código
Relatórios de teste e de segurança, com evidências testes.pdf e zero-vulnerabilidades.pdf — os HTML os substituem
robots.txt e noindex em toda página Qualquer forma de autenticação — repositório público não tem

Critério de aceite

  • O workflow falha na etapa de conferência se qualquer arquivo esperado não chegar ao _site — link quebrado não passa para produção.
  • As seis URLs da tabela acima abrem, com CSS e imagens carregados.
  • Toda página servida traz <meta name="robots" content="noindex, nofollow">; /robots.txt responde com Disallow: /.
  • O alternador de tema, os links da sidebar e as âncoras do TOC funcionam nas páginas do portal.
